# 備品リース契約管理アプリ 仕様書

## 0. 前提・結論
- **目的**: 会社備品のリース契約書・関連書類を一元保管し、リース期限を把握できるWebアプリを構築する。
- **利用者**: 代表者本人1名のみ(シングルユーザー)。
- **技術方針**: Next.js(App Router)+ TypeScript。GitHubにソースを置き、Vercelで自動デプロイ。ファイル本体はVercel Blob、メタデータはVercel Postgres(またはSQLite→Turso)に保存。

---

## 1. 機能要件(優先順位順)

| 優先度 | 機能 | 内容 |
|---|---|---|
| 高 | 契約登録・書類アップロード | 備品ごとに契約情報を入力し、契約書PDF/画像を複数添付できる |
| 高 | 契約一覧・検索・フィルタ | リース会社別・ステータス別・期限別に一覧表示、キーワード検索 |
| 高 | リース期限アラート | 終了日の30/60/90日前をダッシュボードで警告表示(色分け:赤=30日以内など) |
| 中 | 契約詳細ページ | 契約情報+添付ファイルのプレビュー・ダウンロード |
| 中 | ステータス管理 | 契約中/更新予定/解約済み/返却済みなどの状態遷移 |
| 低 | CSVエクスポート | 会計・税務資料用に一覧をCSV出力 |
| 低 | メール通知 | 期限アラートを自分宛にメール送信(任意、Resend等のAPI利用) |

## 2. データモデル(案)

### Lease(リース契約)

**リース会社の選択肢(固定・プルダウン)**
1. 114リース
2. オーシャンリース
3. いよ銀リース

| フィールド | 型 | 説明 |
|---|---|---|
| id | string(UUID) | 主キー |
| equipment_name | string | 備品名(例:複合機、フォークリフト) |
| category | string | 備品種別(OA機器/物流機器/車両など) |
| lessor | enum | リース会社(固定選択:①114リース ②オーシャンリース ③いよ銀リース) |
| contract_number | string | 契約番号 |
| start_date | date | リース開始日 |
| end_date | date | リース終了日 |
| monthly_fee | number | 月額リース料(円) |
| lease_rate | number | リース料率(%)※リース総額に対する年率or月率、社内管理用の参考値 |
| status | enum | 契約中 / 更新予定 / 解約済み / 返却済み |
| location | string | 設置場所・使用部署 |
| memo | text | 自由記入欄 |
| created_at / updated_at | datetime | 自動記録 |

### Document(添付書類)
| フィールド | 型 | 説明 |
|---|---|---|
| id | string(UUID) | 主キー |
| lease_id | string | 紐づく契約ID(外部キー) |
| file_name | string | 元ファイル名 |
| blob_url | string | Vercel Blobの保存先URL |
| file_type | string | pdf / image など |
| uploaded_at | datetime | アップロード日時 |

## 3. 画面構成

1. **ダッシュボード**(`/`)
   - 期限が近い契約の警告一覧(赤:30日以内、黄:90日以内)
   - 契約総数、月額リース料合計
2. **契約一覧**(`/leases`)
   - テーブル表示、キーワード検索・ソート
   - **絞り込みフィルタ**:リース会社(114リース/オーシャンリース/いよ銀リース)、ステータス(契約中/更新予定/解約済み/返却済み)を条件指定(複数選択可、組み合わせ絞り込み可)
3. **契約詳細/編集**(`/leases/[id]`)
   - 契約情報表示・編集、添付ファイルのアップロード・削除・プレビュー
4. **新規契約登録**(`/leases/new`)
   - リース会社は自由入力ではなく、3社(114リース/オーシャンリース/いよ銀リース)からのプルダウン選択とする
5. **CSVエクスポート**(一覧画面からボタンで出力)

## 5. 非機能要件・リスク

- **セキュリティ(確信度:高)**: 契約書には取引先名・金額など機密情報が含まれる。VercelのURLは推測されうるため、Basic認証やパスワード保護を必ず設定する。
- **バックアップ(ここは推測)**: Vercel Blob/Postgresの障害・誤削除に備え、月次で契約データ+ファイルをローカルまたは別クラウドにエクスポートする運用を推奨。
- **コスト(確信度:中、要確認)**: Vercel Hobbyプランは個人・非商用利用が前提とされている場合がある。会社の資産管理用途で使う場合、利用規約上Proプランが必要になる可能性があるため、Vercelの利用規約を確認すること。
- **GitHubへの機密ファイル混入防止**: `.gitignore`でアップロードファイルを確実に除外し、ソースコードのみをリポジトリで管理する。

## 6. 開発ステップ(Claude Codeでの実装順)

- **GitHubリポジトリ**: https://github.com/naoya1109-t/LeaseManagement.git

1. Next.jsプロジェクト初期化 + Vercel Postgres/Blobのセットアップ
2. Leaseテーブルのスキーマ作成・CRUD API実装
3. 契約一覧・検索・フィルタ画面の実装
4. ファイルアップロード(Vercel Blob連携)・添付ファイル表示の実装
5. ダッシュボード(期限アラート)の実装
6. 認証(パスワード保護)の実装
7. CSVエクスポート機能の実装
8. 上記リポジトリへpush → Vercel連携 → 本番デプロイ

### Vercel連携手順(未設定のため追記)

1. https://vercel.com にアクセスし、GitHubアカウントでログイン
2. 「Add New Project」→ `naoya1109-t/LeaseManagement` を選択してImport
3. Framework Presetは自動検出(Next.js)されるはずなのでそのままDeploy
4. デプロイ後、Vercelダッシュボードの「Storage」タブから Postgres と Blob をプロジェクトに追加(自動で環境変数`DATABASE_URL`/`BLOB_READ_WRITE_TOKEN`等が設定される)
5. 「Settings → Deployment Protection」でパスワード保護(または簡易認証)を有効化 ※Hobbyプランでの提供範囲は要確認(確信度:中)
6. 以降、GitHubの`main`へpushするたびに自動で再デプロイされる
